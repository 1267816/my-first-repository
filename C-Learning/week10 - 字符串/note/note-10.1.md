# 第十周：字符串

## 10.1 字符串

### 10.1.1

**字符数组**

```c
char word[]={'H','e','l','l','o','!'};
```

这不是C语言的字符串，因为不能用字符串的方式做计算。

**字符串**

```c
char word[]={'H','e','l','l','o','!','\0'};
```

字符串是以0（整数0）结尾的一串字符。0或'\0'是一样的，但是和'0'不同。
0标志着字符串的结束，但它不是字符串的一部分，计算字符串长度的时候也不包含这个0。
字符串以数组的形式存在，以数组或指针的形式访问，更多的是以指针的形式。
string.h里有很多处理字符串的函数。

**字符串变量**

```c
char *str="Hello"; //指针形式
char word[]="Hello"; //字符数组形式
char line[10]="Hello"; //10代表数组有10个字节大小
```

**字符串常量**
`"Hello"`会被编译器变成一个字符数组放在某处，这个数组的长度是6，结尾还有表示结束的0。
两个相邻的字符串常量会被自动连接起来。

```c
printf("请分别输入身高的英尺和英寸"
    "如输入\"5 7\"表示5英尺7英寸");
```

```c
printf("请分别输入身高的英尺和英寸，\
如输入\"5 7\"表示5英尺7英寸");
```

上面第一段代码是第二周的一个程序，当时就使用了这个特性。如果不使用它，也可以用第二段代码，不过反斜杠下面的那一行需要紧贴这一行的开头，否则空出的制表位也会一并输出。

**字符串总结**
C语言的字符串是以字符数组形态存在的，不能用运算符对字符串做运算，通过数组的方式可以遍历字符串。
唯一特殊的地方就是字符串字面量可以用来初始化字符数组，以及标准库提供了一系列字符串函数。

### 10.1.2

```c
#include <stdio.h>
int main(void)
{
 char *s="Hello World";
 char *s2="Hello World";
 //s[0]='B';
 printf("s=%p\n",s);
 printf("s2=%p\n",s2);
 printf("Here!s[0]=%c\n",s[0]);
 
 return 0;
}
```

注意到，运行上述程序，s和s2输出的值一样，但如果把注释的那一行取消注释，程序会崩溃。
`char *s="Hello world!";`
s是一个指针，初始化为指向一个字符串常量。
由于这个常量所在的地方是代码段，所以实际上s是`const char* s`，但是由于历史原因，编译器接收不带const的写法。
但是，试图对s所指的字符串写入会导致严重的后果。
如果需要修改字符串，应该用数组：
`char s[]="Hello world!";`

```c
#include <stdio.h>
int main(void)
{
 char s3[]="Hello World";
 printf("s3=%p\n",s3);
 printf("Here!s3[0]=%c\n",s3[0]);
 return 0;
}
```

**指针还是数组？**
当我们的程序里面需要一个字符串的时候，到底把它写成指针的形式还是数组的形式呢？

- 数组：这个字符串在这里
  作为本地变量空间自动被回收
- 指针：这个字符串不知道在哪里
  处理参数、动态分配空间
结论：
- 如果要构造一个字符串 --> 数组
- 如果要处理一个字符串 --> 指针

**char*是字符串吗？**
字符串可以表达为`char*`的形式，但`char*`不一定是字符串。
它的本意是指向字符的指针，可能指向的是字符的数组，就像`int*`一样。
只有它所指的字符数组有结尾的0，才能说它所指的是字符串。

### 10.1.3

**字符串输入输出**

```c
char string[8];
scanf("%s",string);
printf("%s##",string);
```

scanf读入一个单词，到空格、tab或回车为止。
但scanf是不安全的，因为不知道要读入的内容的长度。

**安全的输入**

```c
char string[8];
scanf("%7s",string);
```

在%和s之间的数字表示最多允许读入的字符的数量，这个数字应该比数组的大小小1。
那么，下一次scanf从哪里开始呢？

**常见错误**

```c
char *string;
scanf("%s",string);
```

以为char*是字符串类型，定义了一个字符串类型的变量string就可以直接使用了。
由于没有对string初始化为0，所以不一定每次运行都出错。

**空字符串**
`char buffer[100]=""`
这是一个空的字符串，`buffer[0]='\0'`
如果把中括号里面的100去掉，那么这个数组的长度只有1。

### 10.1.4

**字符串数组**
`char **a`
a是一个指针，指向另一个指针，那个指针指向一个字符串。

`char **a` 是**二级指针**：`a` 指向一个“`char *` 类型的变量”，而那个 `char *` 再指向一个字符串的首字符。

可以这样拆：

```c
char **a;
```

- `a`：类型是 `char **`，指向“字符指针”
- `*a`：类型是 `char *`，也就是一个字符串指针
- `**a`：类型是 `char`，也就是某个字符串的第一个字符

常见用途是表示“字符串数组”的另一种形式，例如：

```c
char *names[] = {"Alice", "Bob", "Cindy"};
char **p = names;   // p 指向 names[0]
```

此时：

```c
p[0]   // 等价于 *p，是 "Alice"
p[1]   // 是 "Bob"
p[0][0] // 是 'A'
```

记法：
`char **a` 不是直接存字符串，而是“指向指针的指针”。如果它指向一个指针数组，那么 `a[i]` 就是第 `i` 个字符串。

**程序参数**
`int main(int argc,char const *argv[])`

- `argc`：命令行参数的个数，**包括程序名本身**
- `argv`：参数字符串数组，`argv[i]` 是第 `i` 个参数字符串
- `argv[0]`：通常是程序被调用时的名字
- `argv[argc]`：标准保证为 `NULL`，可作为结束标志

例如运行：

```bash
./hello foo bar
```

则大致是：

```c
argc == 3
argv[0] == "./hello"
argv[1] == "foo"
argv[2] == "bar"
argv[3] == NULL
```

关于 `argv[0]`：
它反映的是“程序被调用时使用的名字”。在 Unix 下，如果通过符号链接运行程序，`argv[0]` 通常是**符号链接的名字**，而不是符号链接指向的真实程序名。

例如：

```bash
ln -s real_prog link_prog
./link_prog
```

此时 `argv[0]` 往往是 `"./link_prog"`，不是 `"real_prog"`。

记法：
`argc` 数个数，`argv` 存字符串；`argv[0]` 是“你怎样调用这个程序”，不一定是程序的真实文件名。

# 第十三周：文件

## 13.1 文件

### 13.1.1

**格式化的输入输出**

printf：`%[flags][width][.prec][hlL]type`

| Flag | 含义 |
| :--- | :--- |
| - | 左对齐 |
| + | 在前面放 + 或 - |
| (space) | 正数留空 |
| 0 | 0填充 |

| width 或 prec | 含义 |
| :--- | :--- |
| number | 最小字符数 |
| * | 下一个参数是字符数 |
| .number | 小数点后的位数 |
| .* | 下一个参数是小数点后的位数 |

prec表示精度。
星号表示动态指定，宽度或精度不写死在代码里，而是由后面的变量传入。例如：
`printf("%*d",5,123);`中的5就传给了星号作为宽度。

| 类型修饰`[hlL]` | 含义 |
| :--- | :--- |
| hh | 单个字节 |
| h | short |
| l | long |
| ll | long long |
| L | long double |

“单个字节”的含义是只截取这个数（转为2进制）的最后8位，并输出。

| type | 用于 | type | 用于 |
| :--- | :--- | :--- | :--- |
| i 或 d | int | g | float |
| u | unsigned int | G | float |
| o | 八进制 | a 或 A | 十六进制浮点 |
| x | 十六进制 | c | char |
| X | 字母大写的十六进制 | s | 字符串 |
| f 或 F | float, 6 | p | 指针 |
| e 或 E | 指数 | n | 读入/写出的个数 |

`%n`比较特殊。它不输出内容，而是把已经打印出的字符个数，存放到对应的参数指针里。例如：

```c
int num;
printf("%d%n\n",12345,&num);
printf("%d",num);
```

第二行就会输出5。

scanf：`%[flag]type`

| flag | 含义 |
| :--- | :--- |
| * | 跳过 |
| 数字 | 最大字符数 |
| hh | char |
| h | short |
| l | long, double |
| ll | long long |
| L | long double |

“跳过”的含义是跳过读取到的数据。例如：
`scanf("%d %*d %d",&a,&b);`
输入`1 2 3`时，2会被跳过，a得到1，b得到3。

| flag | 含义 |
| :--- | :--- |
| * | 跳过 |
| 数字 | 最大字符数 |
| hh | char |
| h | short |
| l | long, double |
| ll | long long |
| L | long double |

| type | 用于 | type | 用于 |
| :--- | :--- | :--- | :--- |
| d | int | s | 字符串（单词） |
| i | 整数，可能为十六进制或八进制 | [...] | 所允许的字符 |
| u | unsigned int | p | 指针 |
| o | 八进制 | | |
| x | 十六进制 | | |
| a,e,f,g | float | | |
| c | char | | |

**`[^.]`**

读取字符，直到遇到方括号内的字符（或集合）为止。`%[^,]` 表示一直读取，直到遇到逗号 `,` 才停止。读取到的内容会作为字符串存入变量。
`%*[^,]` 表示跳过前面的字符，直到遇到逗号。
一种应用如下：

```c
// 需要读取的GPS数据（以逗号分隔）：
// $GPRMC,004319.00,A,3016.98468,N,...
// 用下面的scanf进行读取：
scanf("%*[^,],%[^,],%[^,],...", sTime, sAV, sLati, ...);
```

***printf和scanf的返回值**

printf：输出的字符总数，包括空格、换行符等；
scanf：读入的项目数，即成功匹配并且赋值的变量个数。

在要求严格的程序中，应该判断每次调用scanf或printf的返回值，从而了解程序运行中是否存在问题。

### 13.1.2

**FILE**

```c
FILE* fopen(const char* restrict path,const char* restrict mode); //1
int fclose(FILE *stream); //2
fscanf(FILE*,...); //3
fprintf(FILE*,...); //4
```

1. 用于打开文件
2. 用于关闭文件
3. 用于从文件中读取格式化输入
4. 用于向文件写入格式化输出

**打开文件的标准代码**

```c
FILE* fp=fopen("file","r");
// 尝试以只读模式打开名为"file"的文件
// fp是一个文件指针，用来接收fopen返回的结果
// 如果文件存在且打开成功，fp指向该文件
// 否则，fopen返回NULL
if (fp) {
    // 判断fp是否为NULL，防止段错误
    // 如果打开成功，继续执行
    fscanf(fp,...);
    // 从fp指向的文件中读取数据
    fclose(fp);
    // 关闭文件，释放系统资源
    // 防止泄漏
} else {
    ...
    // 如果文件打开失败，处理错误
}
```

**fopen**

| 模式 | 说明 |
| :--- | :--- |
| r | 打开只读 |
| r+ | 打开读写，从文件头开始 |
| w | 打开只写。如果不存在则新建，如果存在则清空 |
| w+ | 打开读写。如果不存在则新建，如果存在则清空 |
| a | 打开追加。如果不存在则新建，如果存在则从文件尾开始 |
| ...x | 只新建，如果文件已存在则不能打开 |

### 13.1.3

**二进制文件**

其实所有的文件最终都是二进制的。文本文件无非是用最简单的方式可以读写的文件：

- more,tail
- cat
- vi

而二进制文件是需要专门的程序来读写的文件。
文本文件的输入输出是格式化，可能经过转码。

Unix喜欢用文本文件来做数据存储和程序配置；而windows喜欢用二进制文件。

**文本vs二进制**

| 对比维度 | 文本 | 二进制 |
| :--- | :--- | :--- |
| **优势** | 方便人类读写，而且跨平台 | 程序读写快 |
| **缺点** | 程序输入输出要经过格式化，开销大 | 人类读写困难，而且不跨平台（int大小不一致，大小端的问题...） |

**程序为什么要文件**

配置：Unix用文本，Windows用注册表
数据：稍微有点量的数据都放数据库了
媒体：只能是二进制的
现实的工程：程序通过第三方库来读写文件，很少直接读写二进制文件了。

**二进制读写**

```c
size_t fread(void *restrict ptr, size_t size, size_t nitems, FILE *restrict stream);
size_t fwrite(const void *restrict ptr, size_t size, size_t nitems, FILE *restrict stream);
```

注意：FILE指针是最后一个参数，返回的是成功读写的字节数。

**为什么有nitem？**

因为二进制文件的读写一般都是通过对一个结构变量的操作来进行的，于是nitem就是用来说明这次读写几个结构变量。

**可移植性**

这样的二进制文件不具有可移植性，在int为32位的机器上写成的数据文件无法直接在int为64位的机器上正确读出。
解决方案之一是，放弃使用int，而是typedef具有明确大小的类型。更好的方案是用文本。

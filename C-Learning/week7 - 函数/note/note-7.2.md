# 第七周：函数

## 7.2 函数的参数和变量

### 7.2.1

**函数先后关系**
```c
void sum(int begin,int end)
{
    int i;
    int sum=0;
    for (i=begin;i<=end;i++) {
        sum+=i;
    }
    printf("%d到%d的和是%d\n",begin,end,sum);
}
int main(){
    sum(1,10);
    sum(20,30);
    sum(35,45);

    return 0;
}
```
像这样把sum()写在上面，是因为：
- C的编译器自上而下顺序分析你的代码
- 在看到sum(1,10)的时候，它需要知道sum()的样子，也就是sum()要几个参数，每个参数类型如何，返回什么类型，这样它才能检查你对sum()的调用是否正确

**如果不知道**
也就是要把被调用的函数放到main()下面。
```c
#include <stdio.h>
void sum(int begin,int end);
int main(){
    sum(1,10);
    sum(20,30);
    sum(35,45);

    return 0;
}
void sum(int begin,int end)
{
    int i;
    int sum=0;
    for (i=begin;i<=end;i++) {
        sum+=i;
    }
    printf("%d到%d的和是%d\n",begin,end,sum);
}
```
第2行的`void sum(int begin,int end);`叫做函数的原型声明，`int main(){...}`后面的`void sum(...){...}`叫做函数的定义。
当然，编译到定义之后，还会判断声明和定义的类型是否一致。

**函数原型**
函数头，以分号";"结尾，就构成了函数的原型。
函数原型的目的是告诉编译器这个函数长什么样：
- 名称
- 参数（数量及类型）
- 返回类型


在旧版本的一些C教材中，习惯把在一个函数（如`main()`）中会用到的所有函数的声明写在函数的最顶端，调用的函数中变量的定义也这样写。
原型里可以不写参数的名字，但是一般仍然写上。
如：
`void sum(int ,int );`

### 7.2.2

**调用函数**
如果函数有参数，调用函数时必须传递给它数量、类型正确的值。
可以传递给函数的值是表达式的结果，包括：
- 字面量
- 变量
- 函数的返回值
- 计算的结果

**类型不匹配？**
- 调用函数时给的值与参数类型不匹配是C语言传统上最大的漏洞
- 编译器总是悄悄替你把类型转换好，但是这很可能**不是你所期望的**
- 后续的语言，C++/Java在这方面很严格

**传过去的是什么？**
这样的代码能够交换a和b的值吗？
```c
#include <stdio.h>
void swap(int a,int b);
int main() 
{
    int a=5;
    int b=6;
    swap(a,b);
    printf("a=%d b=%d\n",a,b);
    return 0;
}
void swap(int a,int b)
{
    int t=a;
    a=b;
    b=t;
}
```
结果发现：不能。
C语言在调用函数时，永远只能传值给函数。
swap()里的a和b与main()里的a和b虽然同名，但它们之间的联系仅仅是在调用swap()时把5和6分别传给了swap()里的a和b。

**传值**
每个函数有自己的变量空间，参数也位于这个独立的空间中，和其他函数没有关系。
过去，对于函数参数表中的参数，叫做“形式参数”（swap()里的a和b），调用函数时给的值，叫做“实际参数”（main()里的a和b）。
==实际参数不是实际在函数中计算的参数！！！==
==调用函数的时候传进去的是值不是变量！！！==

### 7.2.3

**本地变量**
- 函数每次运行，就产生了一个独立的变量空间，在这个空间中的变量，是函数的这次运行所独有的，称作本地变量
- 定义在函数内部的变量就是本地变量
- 参数也是本地变量

**变量的生存期和作用域**
- 生存期：什么时候这个变量开始出现了，到什么时候它消亡了
- 作用域：在（代码的）什么范围内可以访问这个变量（这个变量可以起作用）
- 对于本地变量，这两个问题的答案是统一的：大括号内——块

**本地变量的规则**
1. 本地变量是定义在块内的。
   - 可以定义在函数的块内
   - 可以定义在语句的块内
   - 甚至可以随便拉一对大括号来定义变量
2. 程序运行进入这个块之前，其中的变量不存在，离开这个块，其中的变量就消失了。
3. 块外面定义的变量在里面仍然有效。
4. 块里面定义了和外面同名的变量则掩盖了外面的。
5. 不能在同一个块里面定义同名的变量。
6. 本地变量不会被默认初始化。
7. 参数在进入函数时被初始化了。

### 7.2.4

**函数没有参数时**
应该写成：`void f(void);`还是`void f();`呢？
建议：不要写后者。
关于main函数不写明确参数表的现象，见下文。

**逗号运算符？**
调用函数时的逗号和逗号运算符怎么区分？
调用函数时的圆括号里的逗号是标点符号，不是运算符。
- `f(a,b)`中的逗号是标点符号
- `f((a,b))`中的逗号是运算符，因为里面加了一个括号

**函数里的函数？**
C语言不允许函数嵌套定义。

**这是什么？**
- `int i,j,sum(int a,int b);`
  这是可以的，表示函数需要两个int参数，并返回一个int，但建议声明单独写在外面。
- `return (i);`
  圆括号没有任何意义，等价于`return i;`，但会让人误以为return是个函数，所以建议不要这么写。

**关于main**
`int main(){...}`也是一个函数。

要不要写成`int main(void){...}`？

建议写。
原因：
- `void` 明确表示：这个函数没有参数。
- `int main()` 在旧式C中，空括号表示“参数信息未指定”，不够明确。
- 在 C++ 里 `int main()` 和 `int main(void)` 基本一样；但在 C 里推荐写 `void`。
- 不要写 `void main()`。标准规定 `main` 的返回类型应为 `int`，`void main()` 不规范、不可移植。

`return 0;`有人看吗？

有，给操作系统/父进程看。
- 大致流程：
C 运行时启动代码 -> 调用 main -> main 返回 int -> 启动代码把返回值交给 exit -> 操作系统收到退出状态

- 通常约定：
  - `0`：成功、正常结束。
  - 非 `0`：失败、出错。具体错误码由程序自己定义。
- 谁看这个值：
  - Linux/macOS shell：`echo $?`
  - Windows cmd：`echo %ERRORLEVEL%`
  - 父进程：`waitpid` 等
  - `make`：根据退出码判断是否成功
  - shell 脚本：`if ./a.out; then ...`
  - IDE：判断程序是否正常结束

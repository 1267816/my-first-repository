## 12.2 编译预处理和宏

### 12.2.1

**编译预处理指令**

`#`开头的是编译预处理指令。
它们不是C语言的成分，但C语言程序离不开它们。
`#define`用来定义一个宏。

```c
#include <stdio.h>

//const double PI=3.14159;
#define PI 3.14159

int main(int argc,char const *argv[])
{
    printf("%f\n",2*PI*3.0);
    return 0;
}
```

在上面的代码中，如果不用`const`，就需要用`#define`来定义`PI`，3.14159是它的值。

**`#define`**

`#define 名字 值`

- 注意：没有结尾的分号，因为不是C的语句
- 名字必须是一个单词，值可以是各种东西
- 在C语言的编译器开始编译之前，编译预处理程序（cpp）会把程序中的名字换成值，这是完全的文本替换
- 文本替换不区分作用域，只要在`#define`之后，全局都能用，而且没有类型检查
- gcc --save-temps
  在终端敲这个命令，可以让编译器在干活时，把中间生成的临时文件保留
  - `.i`文件：预处理后的文件，实现了“完全的文本替换”
  - `.s`文件：汇编代码文件
  - `.o`文件：目标文件（二进制代码）
  - `.a`或`.so`等其他文件：其他中间文件或静态库/动态库

**宏**

如果一个宏的值中有其他宏的名字，也会被替换。
如果一个宏的值超过一行，最后一行之前的行末需要加`\`。
宏的值后面出现的注释不会被当作宏的值的一部分。

**没有值的宏**

`#define _DEBUG`
这类宏是用于条件编译的，后面有其他的编译预处理指令来检查这个宏是否已经被定义过了。

**预定义的宏**

- `__LINE__` ->源代码文件当前所在行的行号
- `__FILE__` ->源代码文件的文件名
- `__DATE__` ->编译时的日期
- `__TIME__` ->编译时的时间
- `__STDC__` ->声明是标准C

### 12.2.2

**像函数的宏**

`#define cube(x) ((x)*(x)*x))`
宏可以带参数。

**错误定义的宏**

`#define RADTODEG(x) (x*57.29578)`
`#define RADTODEG(x) (x)*57.28578`

采用如下的测试程序：

```c
#include <stdio.h>

#define RADTODEG1(x) (x*57.29578)
#define RADTODEG2(x) (x)*57.29578

int main(int argc,char const *argv[])
{
    printf("%f\n",RADTODEG1(5+2));
    printf("%f\n",180/RADTODEG2(1));
    return 0;
}
```

两个输出结果都是错误的。为什么？
因为文本替换没有考虑运算优先级问题，也就是少了括号。

**带参数的宏的原则**

- 一切都要括号
  - 整个值要括号
  - 参数出现的每个地方都要括号

应该写成：`#define RADTODEG(x) ((x)*57.29578)`

**带参数的宏**

可以带多个参数，如：

```c
#define MIN(a,b) ((a)>(b)?(b):(a))
```

也可以组合（嵌套）使用其他宏。

它在大型程序的代码中使用非常普遍，可以非常复杂，如在`#`和`##`这两个运算符的帮助下“产生”函数。
它存在中西方文化差异。部分宏会被inline函数替代。

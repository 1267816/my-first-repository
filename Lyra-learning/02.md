# 第 2 章实操记录：GameMode 的存在端验证

## 🎯 实验目的

通过纯蓝图方式，验证 UE 网络架构的核心规则：同一份逻辑，在服务器与客户端的执行结果是否不同（特别是 GameMode 的获取）。

## 🛠️ 实操步骤（我做了什么）

1. **创建测试环境**：新建空白地图 `L_TestNet`，保持工程干净。
2. **搭建测试蓝图 `BP_DirectorProbe`**：
   - 核心节点：`Event BeginPlay` -> `Get Game Mode` -> `Is Valid` -> `Branch`。
   - 分支输出：True 走向 `Print String ("我是服务器，导演在场")`；False 走向 `Print String ("我是客户端，导演不在")`。
3. **放置与配置**：
   - 将蓝图实例拖入 `L_TestNet` 地图保存。
   - 配置 PIE 运行环境：运行网络模式选 `Play As Client`，玩家数量 `2`，开启 `单进程下运行`（集中输出日志）。

## 📊 运行结果

点击 Play 后，出现两个客户端窗口，屏幕均显示“我是客户端，导演不在”。查看底部的输出日志（过滤“导演”），得到如下记录：

```text
Server: 我是服务器，导演在场
Client 1: 我是客户端，导演不在
Client 2: 我是客户端，导演不在
```

## 🧠 结论与总结

1. **现象吻合预期**：后台服务器成功获取到了 GameMode 并打印“在场”；两个客户端获取到的都是空值，走 False 分支打印“不在”。
2. **架构原理印证**：印证了第 2 章的“岗位表”设计——`GameMode` 作为游戏规则的管理者，只存在于服务器端。客户端上的副本逻辑无法直接访问。
3. **避坑指南**：后续写逻辑时，绝对不要在客户端代码中直接 `Get Game Mode` 并调用其内部方法，否则必定触发空指针。涉及全局规则的调用，必须通过网络 RPC 发送给服务器。

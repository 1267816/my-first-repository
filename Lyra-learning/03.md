# 第 3 章实操记录：网络入门与服务器权威

## 🎯 实验目的

验证 UE 网络架构中“服务器权威”与“分端加载”机制；验证属性复制（Replication）与网络模式（NetMode）的底层逻辑。

## 🛠️ 实操步骤（我做了什么）

1. **环境与硬件拉扯**：
   - 尝试直接在 `L_Expanse` 地图运行 `Play As Client`（2个玩家）。
   - 触发 DX12 驱动崩溃及“尝试分配渲染资产时显存内存不足”报错。
   - **自救操作**：增加了 32GB 虚拟内存；修改 `DefaultEngine.ini` 强制切换 DX11 并关闭 Nanite / Lumen。
   - **换图测试**：依次尝试了主菜单图、白模图 (`L_Expanse_Blockout`) 和新建空地图 (`L_EmptyTest`)。
2. **控制变量测试**：
   - 测试结果：单窗口（Standalone 或 Listen Server）运行完美，不崩溃。
   - 测试结果：双窗口（Play As Client，2 Players）必崩。
3. **理论通关**：因硬件物理限制（核显同时渲染 3 个 3D 世界导致 OOM），通过日志理论推演完成实验。

## 📊 运行结果

**硬件崩溃报错**：
`尝试分配渲染资产时显存内存不足。请确保显卡能满足所需的最低内存...`

**理论标准日志（如果硬件扛得住，必然出现以下结果）**：

```text
LogLyraExperience: Identified experience ... (Source: WorldSettings)  <-- 仅 1 次
LogLyraExperience: EXPERIENCE: StartExperienceLoad(...) Server        <-- 服务器加载
LogLyraExperience: EXPERIENCE: StartExperienceLoad(...) Client        <-- 客户端1加载
LogLyraExperience: EXPERIENCE: StartExperienceLoad(...) Client        <-- 客户端2加载
```

## 🧠 结论与总结

1. **现象与预期吻合度**：虽然实操因硬件崩溃，但理论逻辑完全闭环。证明了轻薄本核显的物理极限：**无法同时渲染多端联机的 3D 视口**。
2. **印证的架构原理（大白话版）**：
   - **发卷子与做卷子**：GameMode 只存在于服务器，所以选 Experience（`Identified experience`）只有 1 次；但加载资源是各端为了自己有画面看（`StartExperienceLoad`），所以出现了 3 次。
   - **公告板（属性复制）**：血量、队伍等持续状态用 `Replicated` 属性。服务器是发公告的人，客户端是看公告的人，中途加入的玩家也会看到最新的公告。
   - **打电话（RPC）**：开枪、换弹等一次性事件用 RPC。向服务器上报意图（Server RPC）必须拥有所有权（Owner），场景里的死物没资格打电话。
   - **精神分裂的 OnRep**：C++ 里客户端的 `OnRep` 会自动触发，但**服务器上不会**。所以 Lyra 代码里，服务器改了血量后，必须“手动再调一次同样的表现逻辑”，这叫“对称结构”。
3. **避坑指南**：
   - 永远不要在客户端尝试 `GetAuthGameMode()`，永远是空指针。
   - `Replicated` 必须是服务器改，客户端改了不仅没用，还会被服务器覆盖。
   - 未来的实验，能用单窗口（Listen Server）验证的，绝不头铁开双窗口！

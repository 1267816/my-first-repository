## 💡 实验一：验证属性标签（UPROPERTY 说明符）

**做了什么：**

1. 新建了一个 Actor 蓝图 `BP_TestSpecifier`。
2. 在左侧创建了一个整型变量 `Health`，默认值填 `100`。
3. 在右侧细节面板，勾选了 **`实例可编辑 (Instance Editable)`**。
4. 将蓝图拖入地图，在右侧面板将某个实例的 `Health` 改为了 `999`。
5. 回到蓝图，勾选变量为 **`临时 (Transient)`**，编译保存。

**观察到了什么：**

- 勾选“实例可编辑”后，我能在地图里随意修改实例的血量（100 改 999）。
- 勾选“临时”后，重新运行游戏或加载，数值会重置回默认的 100。

**对应了什么理论：**

- **`EditAnywhere` / `EditDefaultsOnly`**：对应蓝图里的“实例可编辑”勾选框。勾上就是 Anywhere（哪都能改），不勾就是 DefaultsOnly（只能在蓝图改）。
- **`Transient`**：对应“临时”标签。意思是“不存盘”，每次加载都会恢复到 CDO 默认值，不写入 `.uasset` 资产中。
- **CDO（类默认对象）**：蓝图里填写的 100，就是这个类的“出厂设置”；地图里改的 999，是实例的“覆盖”。

## 💡 实验二：验证 C++ 与蓝图的三种沟通方式（UFUNCTION）

**做了什么：**

1. 在蓝图事件图表里，右键搜出了 `Print String`（打印字符串）。
2. 拉出了红色的 `Event BeginPlay`（游戏开始时执行）。
3. 在左侧“函数(可覆盖)”菜单里，重载了红色的 `ActorBeginOverlap`（碰撞重叠触发）。
4. 将白色执行箭头串联起来。

**观察到了什么：**

- 游戏一运行，`BeginPlay` 后面连的逻辑立刻执行（屏幕打印）。
- 角色走过去撞到碰撞体时，`ActorBeginOverlap` 触发后面的逻辑。

**对应了什么理论：**

- **`BlueprintCallable`**：像 `Print String` 这种能直接搜出来当积木用的节点，是 C++ 写好的，允许蓝图调用。
- **`BlueprintImplementableEvent`**：像 `BeginPlay`，C++ 留出空位让蓝图自己写逻辑，不写就不执行。
- **`BlueprintNativeEvent`**：像 `ActorBeginOverlap`，C++ 提供了默认底子，允许我们在蓝图里“重载/覆盖”它。

## 💡 实验三：验证资产数据校验（原书实验3的完美复现）

**做了什么：**

1. 在内容浏览器顺着路径 `Plugins -> ShooterCore -> Content -> Experiences` 找到了官方资产 `B_ShooterGame_Elimination`。
2. 右键它，选择了 **`创建子蓝图类`**，生成了违规的 `B_TestChild`。
3. 右键 `B_TestChild`，选择 **`资产操作` -> `验证资产`**。
4. 在输出日志（Message Log）中观察结果。

**观察到了什么：**

- 报出红色错误：`[AssetLog] ... Blueprint subclass...`

**对应了什么理论：**

- 引擎底层用 C++ 写的 `IsDataValid` 函数（反射 API）在正常运作。它顺着继承链发现这是一个“蓝图继承蓝图”的违规操作，直接亮红牌。
- 这也证明了反射系统在后台时刻监视着所有类的父子关系。

## ⚠️ 血泪避坑与技巧记录

1. **触摸板受害者**：在蓝图图表里，按住 **空格键** + 鼠标拖动，可以平移画布；点中节点按 **F 键**，可以瞬间聚焦。
2. **安全测试环境**：做测试一定要新建一张 `基础 (Basic)` 空白地图，或者在内容浏览器新建 `MyTest` 文件夹。千万别把测试用的模型/蓝图保存进 Lyra 的官方地图（如 `L_Expanse`）。
3. **找 Actor 父类**：如果新建蓝图时默认列表没有，点左下角的 **`所有类`** 展开搜索。
4. **连线机制**：按住左键从白三角（执行引脚）拖出线，连到另一个白三角。连对时黄字警告会消失。

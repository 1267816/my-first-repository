## 题目

给定一个整数 n，判断能否通过 11,111,1111,11111,111111,… 中的数字，通过多次相加得到 n（数字可重复使用）。例如：

```text
33=11+11+11
144=111+11+11+11
```

输入格式：一行包含一个正整数 n（1≤n≤10^9）。

输出格式：如果能生成 n，输出 "YES"（不带引号），否则输出 "NO"。

输入样例1：

```text
33
```

输出样例1：

```text
YES
```

输入样例2：

```text
69
```

输出样例2：

```text
NO
```

        a[i+1]=10*a[i]+1;

    int isyes=0;
    i=7;
    while (n>=11) {
        if (n>=a[i]) {
            n-=a[i];
        } else {
            i--;
        }
    }

    if (n==0) {
        isyes=1;
    }

    if (isyes==1) {
        printf("YES");
    } else {
        printf("NO");
    }

    return 0;
}

    } else {

## 复盘

- **提交1错在哪**：把「用若干个 11、111、1111…相加凑出 n」当成贪心处理（每次减掉最大的不超过 n 的 repunit）。贪心在这里没有正确性保证：121=11×11 可以凑出，但贪心会先减 111 剩 10，于是判 NO。另外数组只生成到 8 位（a[7]=11111111），题目 n 到 10^9，覆盖不全。
- **提交2错在哪**：方向对了——只需要考虑 11 和 111，更长的 1111=11×101、11111=11×1000+111、111111=111×1001 都能由 11、111 拼出来——但用双重循环枚举 11x+111y=n，复杂度 O(n²)，n 到 10^9 必然超时。
- **提交3为什么对**：设 n=11q+r（0≤r<11）。要让余数 r 被消掉，必须用 r 个 111（因为 11 不改变模 11 的余数，而 111≡1 mod 11）。剩下 n−111r 要能被 11 整除，而 n−111r≡r−111r=−110r≡0 (mod 11) 恒成立。所以只要 n≥111r，就一定能凑出；n<111r 就凑不出。一次取模即可，O(1)。（我在 n≤2·10^5 范围内用完全背包暴力对拍过这个条件，完全一致。）
- **怎么避免**：遇到「若干个固定面额凑数」，先问能不能化成同余/整除条件，别急着贪心或枚举；枚举解法先估复杂度再动手。询问AI拿到解之后，至少把「为什么这样对」补上，否则这题等于没做。

## 题目

### 题目背景

十六进制是一种基数为16的计数系统，使用数字0到9和字母A到F来表示数值。在这种系统中，逢16进1，A～F代表10～15。

### 题目描述

给定一个正整数n和一个有4n位的二进制数（不保证没有前导零），请你求出，该二进制数转化为十六进制表示后共有多少个A。

### 输入格式

第一行输入一个正整数n。
第二行输入一个只由01构成的4n位二进制数，不保证没有前导零。

### 输出格式

一行输出一个整数，表示输入的二进制数用十六进制表示时A的个数。

### 样例

输入：

```text
3
101010111100
```

输出：

```text
1
```

说明：该二进制数用十六进制表示为ABC，其中有一个A。

### 数据范围

- 前20%：n=1
- 前40%：n≤10
- 前60%：n≤1000
- 100%：1≤n≤10⁶

## 提交记录

### 提交1

```c
#include <stdio.h>
#include <string.h>

int main() {
    int n;
    scanf("%d",&n);
    int i,j;
    int cnt=0;
    char array[n][5];

    for (i=0;i<n;i++) {
        scanf("%4s",array[i]);
        if (strcmp(array[i],"1011")==0) {
            cnt++;
        }
    }

    printf("%d",cnt);
    return 0;
}
```

判题结果：答案错误（54 ms / 9124 KB）

## 复盘

- **错在哪**：十六进制里A对应二进制1010，代码比的却是1011（那是B）。这道题的样例是ABC，恰好一个1010、一个1011，数出来都是1，样例就这么蒙对了——这也是它能提交、只是"部分正确/答案错误"的原因。最小反例：n=1、输入1010，应输出1，实际输出0。
- **顺带**：把整个4n位的二进制塞进`char array[n][5]`，n到10⁶就是5MB的栈上变长数组，实测占用9124KB，离栈限制很近。完全不用存——每读4个字符判一次、计数即可，空间O(1)。
- **怎么避免**：进制对应的位权先写在纸上（A=1010、B=1011、C=1100……F=1111），比着写；样例只是验证，别把"样例过"当成"题目过"，自己造一个最小的边界反例再交一次。

## 三、逐题诊断（只看你自己的代码）

| 题 | 你的做法 | 诊断 |
| --- | --- | --- |
| A | 直接输出字符串 | 签到题，没问题 |
| B | `while (t >= a+b) { cnt++; t -= a+b; }`，运行 323 ms | **能过但危险**：t 最大 10⁹、a+b 最小 2，循环最多约 5×10⁸ 次。官方做法是除法一步算出 `t/(a+b)`。同样的题数据再大一点就会超时。 |
| C | 自己写 max 函数 + 两种模式分支 | 没问题，m = 0/1 的语义抓对了 |
| D | 三次错误：先 `int`、再 `long long`、再 `malloc`，最后用 `sum*2` 通过 | **方向对了但绕了远路**。真正的问题不是溢出，而是"每台 MS 的功率在总和里恰好出现两次"这个化简；前三次都在逐台累加 `vs/2`，被整数除法的截断吃掉了小数，所以一直错。 |
| E | 两重循环枚举 + 自己写的距离函数 | 没问题（n ≤ 100，O(n²) 够用） |
| F | 一次扫描维护连续长度 | 标准写法 |
| G | 拆出各位后比较相邻两位 | 没问题 |
| H | 第一版用 `x[i+1]` 越界，段错误；改成 `x[i]` 后通过 | **典型数组越界**：声明了 `int x[n]` 却访问 `x[i+1]`；另外 `ischecked[n+1]` 的声明与初始化范围（`i=1..n`）不一致。 |
| I–M | 无提交 | 见下一节 |

另外两个习惯问题（这次没影响结果，但迟早会咬人）：

- 第三次提交 D 时用了 `malloc` 却没有 `#include <stdlib.h>`（C 语言会隐式声明，返回值被当作 int，很危险）。
- 多处使用变长数组 `int v[n]`。n 小的时候没事，但栈空间有限，n 到 10⁶ 量级就会崩。

## 四、I–M 五题分别缺什么（对照官方题解）

| 题 | 类型 | 需要补的能力 |
| --- | --- | --- |
| I | 2×n 网格的连通性 / 障碍判断 | 网格上的路径搜索（BFS/DFS）或"找拦路条件"的推理 |
| J | 简单博弈 | 取石子类博弈的必败态规律（3 的倍数） |
| K | 构造 + 贪心 | 从目标反推操作次数（相邻不同、首尾相同各贡献一次翻转） |
| L | 贪心 + 推公式（Easy） | 每回合先看能不能输出答案，再决定攻击还是回血（交换论证） |
| M | 二分 + 数学 + long long（Hard） | 把"最少攻击次数"化成单调函数后二分；x、y 到 10¹² 必须 long long |

这五题正好覆盖你目前最缺的三块：**网格搜索、博弈规律、二分与贪心推导**。

## 五、和 12 月暨大新生赛的对照

- 暨大新生赛：个人赛、5 小时、约 12–13 题、牛客判题、罚时 20 分钟——和这场（3 小时、13 题、ACM 赛制）
  几乎是同一种形式，**这次相当于一次实弹预演**。
- 参考 2021 年暨大新生赛（13 题，5 道题无人通过，最高过题数 8 道）：你 3 小时拿到 8 题，
  说明**进入校内前列是有竞争力的**；但要注意两点：那次的 8 题是在 5 小时里拿到的；
  暨大有信竞基础的选手也在竞争（这次榜单上就有 10 题的校内选手）。
- 所以接下来要补的不是"再多学几个算法"，而是：
  1. **止损纪律**：单题 25–30 分钟没有实质进展就跳过；开赛先花 10–15 分钟扫一遍所有题。
  2. **补齐三类题**：网格搜索、博弈规律、二分/贪心推导，各 5–8 道；像 J 这种"想明白就 3 行"的题绝不能放过。

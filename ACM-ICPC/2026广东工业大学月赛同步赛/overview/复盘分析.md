## 三、逐题诊断

### 该拿却没拿的（重点）

**D. 课后作业（300/364，82% 的人过）** —— 官方题解给的思路是**本地打表**：x 只有 0–11，
自己在本地暴力跑出答案，提交时直接 `switch` 输出。你的做法是「只由 2 组成的三进制数 + 手推迭代」，
思路从根上就走偏了（乘法持久性不是只有 2 组成的数才需要），交了一次答案错误后就放掉了。
**这是全场最大的一个漏点：82% 的人做出来，而且官方明确允许打表。**

**N. 不太整齐的队伍（174/198，88% 的人过）** —— 你一次都没有提交。这道题的正解是分类讨论：
K > n 时答案直接是 n（区间整个数组的 mex 不会超过 n）；K ≤ n 时用双指针滑窗 / 记录每个数最后出现的位置，
找不含 0…K 全体的最长区间。**这正好是阶段 3 的双指针题型**，不是超纲题。

**E（94/118）、I（36/46）** —— 二分答案 + 树形 DP、期望 + 逆元，都在你的九周计划之外（阶段 4 之后），
不做是合理的，不用背这个锅。

### 做出来的那 5 题，代码层面的问题

1. **K（435 ms / 23.8 MB）**：开了 `(2n−1)²` 的二维数组、逐圈 `++` 填分。n ≤ 1000 时 size = 1999，
   约 400 万个 int，刚好活在限制里。正解是 O(1)：`n − max(|x−n|, |y−n|)`，或者干脆不存格子、只对 k 个点算分。
   这和 10-10 那场 B 题的「3.2 亿次循环」是同一个毛病——**能过但没走正路**。
2. **B（`char s[m]` + `scanf("%s", s)`）**：m 最大 10⁶，`%s` 没有宽度限制，靠输入不越界才没炸。
   应该写 `char s[m+1]` 或用带宽度限制的读法。
3. **C（两次 WA）**：前两版 B30 插入只写了 `b[j]=rate[i]; break;`，**没做后移**，
   等于把第 j 位覆盖掉；第三版补了 `for (k=29;k>j;k--) b[k]=b[k-1];` 才通过。
   注意：原材料里 C 的代码在「ACC 比较」那一行的方向与题面相反（题面是 a ≥ 97.50 才计分），
   很可能是图片转文字时转反了，以牛客提交记录为准。
4. **变长数组**：`double d[N]`、`double rate[N]`（N 到 2×10⁵）约 3.2 MB，放在栈上有崩的风险，
   不同评测机的栈上限不一样；比赛里更稳的写法是全局数组或 `malloc`。

## 五、下一步动作

1. **补 D**：本地写暴力打表 0–11，顺便练一个习惯——**看到范围极小（x ≤ 11）先想能不能打表**。
2. **补 N**：双指针 + 记录每个数最后出现位置；K > n 直接输出 n。
3. **量化止损**：单题 30 分钟没有「能提交的思路」就跳；跳过之后按通过率从上往下扫（这场 D 的 82%
   是个明显信号，不该留到最后）。
4. **代码三条自查**：VLA 换全局数组 / `malloc`；`scanf("%s")` 加宽度；手写插入/排序写完先自查「后移」这一步。
5. **K 重写一遍公式版**，对比 435 ms / 23.8 MB → 0 ms / 0 额外内存。
